# OverlayAI

OverlayAI is an external tool for Counter-Strike 2 that overlays game information on top of the screen using a separate window. It does not inject code into the game. It reads the game process memory using ReadProcessMemory / WriteProcessMemory and renders everything in its own window above CS2.

The project is written in C++ and uses DirectX 11 for rendering and ImGui for the menu interface. All game data is obtained by reading memory addresses (offsets) generated by cs2-dumper.

## 1. What OverlayAI does

OverlayAI offers the following features, all from an external process:

**Visuals (ESP)**
- Boxes around players (enemies in red, allies in blue)
- Player names with visibility-based coloring (green = visible, red = not visible)
- Health and armor bars
- Character skeleton (bones) rendering
- Weapon icons and ammo display
- Bomb, defuse kit, helmet and armor indicators
- Grenade trajectory tracing

**Aim**
- Triggerbot: automatically fires when the cursor is on an enemy
- Aimlock: adjusts aim toward the nearest enemy within a configurable angle
- R8 revolver support with cocking logic
- Filters: visible only, no allies, ignore when flashed or in smoke

**Movement**
- Bunny Hop: automatic jump when hitting the ground
- Strafe assistance

**Utility**
- Radar hack: shows all player positions on a minimap
- Anti-flash: reduces or eliminates flashbang blinding
- Anti-smoke: removes smoke grenade smoke
- Custom smoke color
- Glow: makes players and objects glow
- Custom crosshair
- Spectator list (who is watching your match)
- Bomb info on screen (time, site, defuse status)

**Inventory**
- Inventory Changer: modifies skins, knives, gloves and agents in the local inventory
- Offline catalog of all game items
- Item preview
- Save and load custom items
- Communication with the game via IPC (inter-process communication)

## 4. How to build

1. Open `OverlayAI.sln` with Visual Studio 2022
2. Select the "Release" configuration and "x64" platform
3. Make sure the Windows SDK is installed
4. Build the solution (Build > Build Solution or Ctrl+Shift+B)
5. The executables are generated in the x64/Release/ folders of each subproject

Projects included in the solution:
- OverlayAI (main project, produces OverlayAI.exe)
- OverlayAI.InventoryBridge (inventory bridge DLL)
- OverlayAI.InventoryHost (inventory host process)
- OverlayAI.InventoryTests (automated tests)
- OverlayAI.PanoramaProbe (Panorama diagnostic tool)

Note: the offsets in `OverlayAI/src/Offsets.cpp` and `OverlayAI/Source.cpp` may be outdated. If the game has been updated, use cs2-dumper to generate new offsets and update those files.

## 5. How to run

1. Build the project (see previous section)
2. Run OverlayAI.exe as administrator (right-click > Run as administrator)
3. Open Counter-Strike 2
4. OverlayAI will detect the game window automatically
5. Press INSERT to open/close the menu
6. Configure the options you want from the menu tabs
7. Press END to close the program (panic bind)

Default keybindings:
- INSERT: open/close menu
- END: close program (panic)
- ALT (hold): triggerbot and aimlock
- SPACE (hold): bunny hop

These keys can be changed from the menu in the Misc tab.

## 6. Project architecture

OverlayAI is an external process. This means:

1. It does not inject a DLL into CS2
2. It does not execute code inside the game thread
3. It reads game data using ReadProcessMemory (Windows API)
4. It writes data to the game using WriteProcessMemory (for glow, anti-flash, etc.)
5. It draws everything in a separate window that overlays the game

Operating flow:

```
CS2 (game process)
    |
    v
ReadProcessMemory / WriteProcessMemory
    |
    v
OverlayAI reads: positions, health, team, weapons, offsets
    |
    v
OverlayAI processes: ESP, aim, triggerbot, glow, inventory
    |
    v
OverlayAI draws: overlay window with DirectX 11 + ImGui
    |
    v
Player's screen (overlay on top of CS2)
```

The inventory system is more complex and uses a bridge that communicates via IPC (named pipes) with an internal module that interacts with Panorama (CS2's UI system).

## 8. Modules and features (detailed explanation)

### 8.1 Memory (Memory.cpp / .h)

The foundation of everything. OverlayAI needs to read game data (health, position, team) and for that it accesses the CS2 process memory. It uses Windows API functions ReadProcessMemory and WriteProcessMemory. It also finds game modules (client.dll, engine2.dll) and gets their base addresses.

### 8.2 Offsets (Offsets.cpp / .h)

Offsets are addresses within the game memory that point to specific data: the player list, each player's position, health, team, etc. These values change every time Valve updates CS2. OverlayAI includes pre-loaded offsets but they can be updated with cs2-dumper or from an external file.

### 8.3 Entities (Entity.cpp / .h)

This module reads information about each player in the game. It iterates through CS2's entity list and builds a snapshot with: 3D position, health, team, name, armor, helmet, current weapon, visibility state. This snapshot is updated every frame and used by everything else (ESP, triggerbot, aimlock, radar, etc.).

To avoid threading issues (the overlay draws on one thread while the game runs on another), it uses a double-buffer system: writes to one buffer while the other is being read, then swaps them atomically.

### 8.4 ESP (Esp.cpp / .h)

ESP stands for "Extra Sensory Perception". It is the feature that draws information about players on screen:

- Boxes (rectangles) around each player
- Names with green color (visible) or red (not visible)
- Health bars (green to red based on amount)
- Armor bars
- Skeleton (lines connecting character bones)
- Weapon icons
- Current weapon ammo
- Bomb, defuse, helmet indicators

To draw all this, it converts 3D world positions to 2D screen coordinates using WorldToScreen (see 8.5).

### 8.5 Coordinate transform (WorldTransform.cpp / .h)

CS2 uses 3D coordinates to position everything in the world. But the screen is 2D. This module converts a position (X, Y, Z) from the game world to (X, Y) screen coordinates. It uses the game's view matrix, which is a 4x4 matrix that defines how the world is seen from the player's camera.

### 8.6 Drawing (Draw.cpp / .h)

Basic drawing functions on screen used by all modules:
- DrawBox: draws a rectangle (for ESP)
- DrawLine: draws a line (for skeletons, trajectories)
- DrawText: draws text (for names, health)
- DrawCircle: draws a circle (for aimlock FOV)

Everything is drawn using ImGui over the DirectX 11 overlay window.

### 8.7 Triggerbot (Triggerbot.cpp / .h)

The triggerbot automatically fires when the cursor is on an enemy. It works as follows:

1. Each frame, it reads the cursor position on screen
2. It checks if there is an enemy under the cursor (using the entity snapshot)
3. If there is an enemy and conditions are met (visible, not ally, etc.), it simulates a mouse click
4. It includes a configurable delay so it is not instant
5. It has special logic for the R8 revolver: handles cocking and cooldown

Configuration:
- Activation key (default: ALT)
- Delay in milliseconds
- Only fire at visible targets
- Do not fire at allies
- Allow or not when flashed/in smoke

### 8.8 Aimlock (Aimlock.cpp / .h)

Aimlock helps with aiming. Each frame:

1. It calculates which enemy is closest to the center of the screen
2. It verifies that the enemy is within the configured FOV angle (e.g. 6 degrees)
3. If the key is held (ALT), it smoothly adjusts aim toward the enemy's head/torso/legs
4. Smoothing makes the movement gradual rather than snappy
5. It can draw a circle on screen showing the FOV

### 8.9 Bunny Hop (Bhop.cpp / .h)

Makes the character jump automatically when hitting the ground, allowing faster movement with bunny hopping. It reads the character state (in air or on ground) from memory and simulates the jump key when the character touches the ground. Includes strafe assistance for better air control.

### 8.10 Glow (Glow.cpp / GlowWriter.cpp / OtherGlow.cpp)

Glow makes players and objects shine in the game, similar to how players glow in deathmatch mode. There are two implementations:

Native glow (Glow.cpp): writes directly to the game's CGlowProperty structure in memory. Allows configuring color by visible/invisible and intensity.

OtherGlow (OtherGlow.cpp): alternative rendered on the overlay instead of using the game's system. Safer because it does not write to game memory.

### 8.11 Anti-flash (AntiFlash.cpp / AntiFlashPatch.cpp)

Reduces or eliminates the blinding effect when a flashbang explodes. Two methods:

AntiFlash.cpp: reads the player's flash alpha value and, if it exceeds a threshold, reduces it to the configured percentage (0% = no blinding, 100% = normal blinding).

AntiFlashPatch.cpp: patches game memory directly so the flashbang effect is not applied.

### 8.12 Anti-smoke (AntiSmoke.cpp)

Removes smoke from smoke grenades to see through them. It reads the smoke state in game memory and disables it when the effect exceeds a threshold.

### 8.13 Smoke color (SmokeColor.cpp)

Allows changing the color of smoke grenades. Writes RGB values to the smoke structure in memory.

### 8.14 Bomb (Bomb.cpp / BombInfo.cpp / .h)

Detects and displays information about the bomb:
- Whether it is planted and at which site (A or B)
- Time remaining until explosion
- Whether someone is defusing and how much is left
- Defuse kit status

### 8.15 Radar (RadarHack.cpp / .h)

Draws a mini-radar in a screen corner showing all player positions, even those behind walls. Converts 3D world positions to a 2D mini-map.

### 8.16 Skeleton (Skeleton.cpp / .h)

Draws lines connecting each character's bones on screen. CS2 stores the position of each bone (head, torso, arms, legs) and this module reads them and connects them with lines. Allows seeing the enemy's exact posture.

### 8.17 Spectator list (SpectatorList.cpp / .h)

Shows who is spectating your match. Reads each player's connection state and lists those in spectator mode watching you.

### 8.18 Grenade trajectory (GrenadeTrajectory.cpp / .h)

Draws the path of grenades in the air. Tracks active grenade positions and draws a line showing their trajectory.

### 8.19 Weapon icons (WeaponIcons.cpp / .h)

Draws weapon icons on screen for each player. Uses an icon font (obs_icons.ttf) containing symbols for each CS2 weapon.

### 8.20 Crosshair (Crosshair.cpp / .h)

Draws a custom crosshair in the center of the screen. Useful when playing with the game's default crosshair disabled.

### 8.21 Menu (Menu.cpp / .h)

Draws the program's graphical interface. Organized in tabs:

1. Home: start panel with general information
2. Visuals: ESP options (boxes, names, bars, skeleton, glow, etc.)
3. Aim: triggerbot and aimlock options
4. Movement: bunny hop and strafe assist options
5. Inventory: Inventory Changer (skins, knives, gloves, agents)
6. Misc: anti-flash, anti-smoke, radar, crosshair, spectators, bomb, keybinds

Each tab has sliders, checkboxes and color pickers.

### 8.22 Configuration (Config.cpp / .h)

Saves and loads all program configuration. Settings are stored in .cfg files in the configs/ folder. Allows:
- Save/load ESP configuration
- Save/load named profiles
- 3 preload slots (quick switch between 3 configurations)
- Reset to factory defaults

### 8.23 Localization (Localization.cpp / .h)

Translation system that allows the menu to be displayed in different languages. Translates interface texts based on the selected language.

### 8.24 Overlay (Overlay.cpp / .h)

Creates and manages the overlay window. This window:
- Is transparent (no borders, no title bar)
- Draws on top of CS2
- Lets clicks pass through to the game when the menu is closed
- Captures clicks when the menu is open
- Uses DirectX 11 for rendering and DwmFlush for monitor synchronization

## 9. Inventory system (Inventory Changer)

The Inventory Changer is the most complex module in the project. It allows modifying the player's local inventory items (skins, knives, gloves, agents) without connecting to Steam or modifying the real inventory.

### Safety limits

- Does not create, modify or claim objects in Steam
- Does not send fake messages to the Game Coordinator
- Does not make items visible to other players
- Does not implement VAC evasion
- Restores any changes when deactivating or closing OverlayAI

### How it works

CS2 builds the inventory screen using Panorama scripts that call InventoryAPI. The Inventory Changer works in several layers:

1. Catalog (InventoryCatalog.cpp): contains the list of all game skins, knives, gloves and agents with their metadata (name, rarity, min/max wear, etc.). Data is generated with tools/GenerateInventoryCatalog.ps1.

2. Store (InventoryStore.cpp): maintains the local collection of modified items the user has created or equipped.

3. Validator (InventoryValidator.cpp): validates that each item is correct before applying it (definition index exists, paint kit associated with weapon, wear within limits, StatTrak allowed, etc.).

4. Persistence (InventoryPersistence.cpp): saves and loads items to a file so they persist between sessions.

5. Preview (InventoryPreview.cpp): shows a preview of items in the menu.

6. Protocol (InventoryProtocol.cpp): defines the message format between the overlay and the game module.

7. IPC (InventoryIpcController.cpp / InventoryIpcServer.cpp): inter-process communication using named pipes (\\.\pipe\OverlayAI.Inventory.v1).

### Music Kits flow

Music Kits are the first fully implemented category:

1. The user selects a Music Kit from the menu
2. OverlayAI writes the Music ID to the player's inventory structure
3. The game shows the Music Kit as if it were the equipped one
4. When OverlayAI is closed, the original value is restored

### Other categories

Weapons, knives, gloves and agents are in the catalog but require the Panorama bridge to be fully applied, since they need to interact with the game's UI system (see section 10).

## 10. Panorama bridge

Panorama is CS2's user interface system (used by Valve in all Source 2 games). The Panorama bridge allows OverlayAI to create an inventory interface inside the game.

### Research

The team investigated the game's panorama.dll and panoramauiclient.dll modules. It found that:
- Both export CreateInterface
- PanoramaUIEngine001 and PanoramaUIClient001 are registered
- But there is no public export for creating panels or executing JavaScript
- gameinfo.gi has AllowCustomGameUI set to 0, so the client rejects addon layouts

### Bridge architecture

The bridge uses a separate internal module (OverlayAI.InventoryBridge) that:
1. Resolves the verified Panorama interface from CreateInterface
2. Executes UI operations on the correct Panorama thread
3. Loads prototype resources (XML, CSS, JS)
4. Connects to the overlay via named pipe IPC
5. Mounts a panel with the modified inventory items

### Interface state

The frontend ABI defines:
- Version 2
- Namespace: OverlayAILocalInventory
- Unique root: OverlayAILocalInventoryRoot
- Callback: OverlayAIPanoramaBridgeSend(json)
- States: Unavailable -> InterfaceResolved -> UiContextReady -> PanelMounted -> Connected

### Third-party audit

A third-party Inventory Changer (berserkv2.dll) was statically reviewed to understand how internal item injection works. It was found to create CEconItem objects, insert them into the local SOCache and notify via SOCreated. Several of its critical signatures no longer match the current CS2 build.

## 11. Configuration and profiles

OverlayAI stores all its configuration in .cfg files in the configs/ folder.

File format:
- Text files with key=value pairs
- One file per aspect (ESP, aim, triggerbot, etc.)
- Profiles with custom names

Available profiles:
- slot1.cfg, slot2.cfg, slot3.cfg: three quick-switch slots
- Custom profiles with any name

Menu functions:
- Save current configuration
- Load a saved profile
- Delete a profile
- Reset to factory defaults
- Switch between the 3 slots with one click

## 13. Legal and safety notices

This project is for educational and research purposes.

- OverlayAI does not evade VAC or any anticheat system
- Does not modify game or Steam files
- Does not send data to external servers
- Does not create or modify items in the real Steam inventory
- Inventory Changer changes are local and restored on close
- Using this software on official servers may violate Valve's terms of service

The project contains no network connections, automatic downloads, webhooks or credential theft. All source code is available for audit.
